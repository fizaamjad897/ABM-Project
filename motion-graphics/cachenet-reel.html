Simulate a distributed cache, agent by agent.

CacheNet models cache nodes, clients, a load balancer and an origin database as independent agents on a discrete-event clock. Run it and watch the hit ratio move — including the moment a node dies and the keyspace re-warms without it.

One write, one read, six events

Nothing in the model is scheduled by hand. This is the sequence the engine produces for a single key when a write lands just before a read.

0 ms
Client writes

A client agent puts a new value for one key onto the queue.

5 ms
Origin accepts

The database records the write and issues invalidations.

10 ms
Nodes invalidate

Every cache node holding that key drops its copy.

15 ms
Client reads

A read for the same key reaches the load balancer.

20 ms
Cache miss

The routed node no longer holds the key and asks the origin.

30 ms
Client answered

The value returns, and the next read on that key will hit.

Seven agents, one clock

Each agent only knows its own state and the messages it receives. Everything on the dashboard comes out of those local rules.

load_balancerRoutes each request to a node by key hash, keeping affinity stable.
service_nodeHolds an LRU cache, answers reads, honours invalidation and TTL.
clientGenerates the read and write traffic that drives the model.
databaseThe source of truth. Serves misses and invalidates on write.
networkApplies latency and loss to every message between agents.
chaos_monkeyKills or degrades nodes at random to test what the cluster does next.
observerSamples hits, misses and latency, and streams them to this interface.
